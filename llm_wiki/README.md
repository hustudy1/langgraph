# llm_wiki 가이드

가이드 버전: `v0.5.0` (최종 갱신: 2026-07-14)

이 폴더는 **프로젝트에서 AI 코딩 도구를 사용할 때 기초가 되는 지시사항 묶음**이며,
`llm_wiki`라는 이름의 git 저장소로 관리한다. 새 프로젝트를 시작할 때 이 폴더를
프로젝트 루트에 `llm_wiki/` 이름 그대로 복사해서 일관된 규칙으로 작업하게 만드는 것이 목적이다.
지시 내용은 표준 Markdown으로 작성해 다양한 AI가 읽을 수 있게 유지하되, 자동 연결과 검증된
운영 절차는 VS Code 등에서 로컬 파일에 접근할 수 있는 Claude Code와 Codex를 우선 지원한다.

## 폴더 구성

| 파일 | 용도 |
|------|------|
| `00_AI_INSTRUCTIONS.md` | AI에게 매 세션 주입하는 **핵심 지시사항** (6대 원칙 + 행동 규칙) |
| `01_WRITING_GUIDELINES.md` | llm_wiki 문서를 **생성·갱신하는 AI가 유의해야 할 사항** (공식 문서 근거 포함) |
| `02_HANDOVER_TEMPLATE.md` | 인수인계 문서 템플릿. 복사해서 `llm_wiki/HANDOVER.md`로 사용 |
| `03_REFERENCES.md` | 이 가이드의 근거가 된 공식 문서 출처 목록 |

## 새 프로젝트에 적용하는 방법

1. 이 저장소를 프로젝트 루트에 `llm_wiki/` 이름으로 복사한다.
   git clone으로 받았다면 복사본 안의 `.git` 폴더를 삭제한다
   (삭제하지 않으면 프로젝트 저장소가 이 폴더의 파일을 추적하지 못한다).
2. 프로젝트 운영 규칙에 따라 `llm_wiki/` 전체를 Git에 포함한다.
3. VS Code의 Claude Code 또는 Codex에서 프로젝트를 열고 아래의 표준 시작 요청을 한 번 입력한다.
   연결 파일과 `HANDOVER.md` 준비는 AI가 자동으로 수행한다.

## AI에게 요청하는 방법

프로젝트를 처음 시작할 때 사용자는 AI에게 아래 한 문장만 요청하면 된다.

> `llm_wiki 참고해서 앞으로 프로젝트 진행해줘.`

이 문장은 이후 프로젝트 작업 전체에 `llm_wiki/`를 적용하라는 표준 시작 요청이다.
AI는 사용자에게 문서별 읽기 순서나 인수인계 작성 방법을 다시 설명해 달라고 요구하지 않고,
아래 작업을 스스로 수행한다.

- 프로젝트 루트를 확인하고 `README.md`, `00_AI_INSTRUCTIONS.md`, `01_WRITING_GUIDELINES.md`를 읽는다.
- Claude Code와 Codex 양쪽에서 규칙이 로드되도록 프로젝트 루트에 연결 파일
  (`CLAUDE.md`, `AGENTS.md`)을 생성하거나 보완한다.
- `llm_wiki/HANDOVER.md`를 읽고, 없으면 구현·수정 작업일 때 `02_HANDOVER_TEMPLATE.md`로 만든다.
  작업이 끝나면 현재 상태·검증 결과·다음 할 일을 갱신한다.
- Git 저장소라면 변경 상태를 정리해 보고하고, `commit`과 원격 `push`는 실행 직전에 각각 승인받는다.

이 개요의 **정확한 단계·연결 파일 내용·읽기 목록·우선순위는 `00_AI_INSTRUCTIONS.md`의
"행동 규칙"과 "코딩 작업 안전 규칙"을 단일 기준으로 한다.** 세부 규칙이 충돌하면
`00_AI_INSTRUCTIONS.md`가 우선한다.

사용자는 이후 작업마다 `llm_wiki`를 다시 언급할 필요가 없다. 다만 새 AI 세션이나 도구가
이전 대화를 공유하지 않는 환경에서는 프로젝트 루트의 `AGENTS.md` 또는 `CLAUDE.md` 연결을
사용해 이 규칙이 자동으로 로드되게 한다.

이 자동 연결은 VS Code 등에서 프로젝트 파일을 읽고 쓸 수 있는 Claude Code와 Codex를
공식 지원 대상으로 한다. 다른 AI 도구는 표준 Markdown 문서를 직접 읽을 수 있지만 연결 파일의
이름과 자동 로딩 방식은 도구마다 다르므로 자동 동작을 보장하지 않는다. 일반 Claude·ChatGPT 웹
대화처럼 로컬 프로젝트 파일에 접근할 수 없는 환경에서는 저장소 연결이나 파일 업로드가 별도로 필요하다.

## 버전과 동기화

- 프로젝트에 복사한 `llm_wiki/README.md`의 가이드 버전을 유지한다.
- 이 원본 가이드를 갱신하면 버전을 올리고, 적용 대상 프로젝트의 `llm_wiki/`와 차이를 비교해 반영한다.
- 프로젝트별로 바꾼 규칙은 `llm_wiki/HANDOVER.md` 또는 프로젝트 전용 문서에 이유와 함께 기록한다.
- 서로 다른 프로젝트의 `llm_wiki/`가 달라질 수 있다. 공통으로 유용한 변경만 이 원본 가이드에 되돌려 반영한다.

## v0.5.0 변경 사항

- 구현·수정 작업마다 `HANDOVER.md`의 현재 상태와 검증 결과를 확인하고 갱신한다.
- Git 저장소에서는 작업 후 변경 상태와 권장 커밋 메시지를 사용자에게 보고한다.
- `commit`과 원격 `push`는 실행 직전에 항상 사용자에게 묻고 승인받은 경우에만 수행한다.
- 복잡하거나 후속 판단이 필요한 답변에는 사용자가 이어서 물을 법한 예상 질문을 정확히 1개 제시한다.
- 지시 계층, 읽기 전용 요청, 도구 권한에 관한 예외를 명확히 했다.
- Codex의 `AGENTS.md` 탐색 방식과 공식 근거를 추가했다.
- 표준 시작 요청 시 `CLAUDE.md`와 `AGENTS.md`를 모두 자동으로 연결한다.

## 운영 원칙

- 세션 시작 시 자동으로 불러오는 핵심 AI 지시 파일은 **짧고 구체적**으로 유지하고
  파일당 200줄 이하를 목표로 한다. 이 기준은 일반 README, 설계 문서, 소스 코드,
  테스트 파일에는 적용하지 않는다.
- 규칙이 서로 모순되면 AI가 임의로 하나를 고른다. 주기적으로 검토해서 낡은 규칙을 지운다.
- 이 문서들은 "맥락"이지 "강제 장치"가 아니다. 반드시 막아야 하는 행동은 도구의
  권한 설정(permissions)이나 hook 같은 기술적 수단으로 막는다.
- 시스템·개발자·사용자 지시, 도구 권한과 충돌하면 더 높은 지시와 기술적 제약을 따른다.
